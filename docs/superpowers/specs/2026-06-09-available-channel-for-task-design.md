# 新建任务可用通道接口设计

## 目标

在“新建任务”时，只展示当前没有被运行中任务占用的通道。

## 规则定义

这里的“可用通道”定义为：

- 通道存在
- 当前没有其他运行中任务占用该通道

运行中任务判定规则：

- `runtime.is_running = true`
- 或 `runtime.status in ["running", "starting", "restarting"]`

## 设计方案

新增专用接口：

- `GET /channels/available-for-task`

返回值格式与普通通道列表保持一致：

```json
{
  "items": []
}
```

## 前端改动

- 新建任务弹窗不再直接使用全部通道列表
- 改为使用“可用通道列表”
- 如果当前没有可用通道：
  - 下拉框为空
  - 创建时仍由前端校验 `channel_id` 非空

## 后端职责

- `ChannelService` 负责计算可用通道
- 路由层只暴露专用接口
- 最终启动任务时，`TaskService.start_task()` 仍保留二次校验，防止并发下出现脏数据

## 好处

- 新建任务体验更清晰
- 与“同一通道同一时刻只允许一个运行中任务”的规则保持一致
- 过滤逻辑统一在后端，第三方系统也可复用
