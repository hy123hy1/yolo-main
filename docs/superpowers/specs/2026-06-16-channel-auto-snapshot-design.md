# 通道接入自动抓底图设计

## 目标

让通道在“接入成功”后自动抓取一张底图并落库，不再依赖手动调用刷新底图接口。

适用范围：

- 本地手动新建通道
- WVP 通道同步

核心要求：

- 抓图失败不能影响通道创建或同步成功
- 抓图成功后，`channels` 表和通道 JSON 都要写入 `snapshot_url`、`snapshot_path`
- 前端现有的手动抓图接口继续保留，作为补抓和人工刷新能力

## 当前问题

当前流程中，`create_channel()` 和 `sync_wvp_channels()` 只负责把通道元数据落盘/落库。

底图只有在后续调用 `POST /channels/{channel_id}/snapshot` 时才会真正生成，因此会出现两个问题：

- 通道刚接入时数据库中没有底图信息
- 后续依赖底图的功能需要额外人工触发一次抓图

## 方案对比

### 方案 A：创建/同步后异步抓图（推荐）

- 通道先创建或同步成功
- 成功返回后，后台异步触发一次抓图
- 抓图成功则更新 `snapshot_url`、`snapshot_path`
- 抓图失败只记日志，不影响主流程

优点：

- 不阻塞创建和同步接口
- 用户体验符合“通道接进来就有底图”
- 对不稳定流更友好

缺点：

- 接口返回时，底图字段可能会有一个很短的异步延迟

### 方案 B：创建/同步时同步抓图

- 接口内部先抓图，再返回创建/同步结果

优点：

- 接口返回时底图一定已经写好

缺点：

- 接口明显变慢
- 弱网、慢流、失效流会拖慢整个接入过程

### 方案 C：定时任务补抓

- 先接入通道
- 后台定时扫描缺少底图的通道并补抓

优点：

- 主流程最稳

缺点：

- 不满足“刚接入就尽快有底图”

## 最终设计

采用方案 A。

### 1. 触发时机

#### 本地新建通道

`ChannelService.create_channel()` 在通道 JSON 保存成功后，异步触发一次自动抓图。

#### WVP 同步通道

`WVPService.sync_channels()` 在每个通道落盘成功后，异步触发一次自动抓图。

#### WVP 刷新播放地址

`refresh_channel_source()` 默认不强制重抓底图。

仅当以下条件满足时允许补抓：

- 当前没有 `snapshot_path`
- 或 `snapshot_path` 指向的文件不存在

这样可以避免每次上游地址刷新时都重复抓图。

### 2. 抓图规则

新增一层“自动抓图”内部能力，复用现有 `snapshot()` 逻辑，不复制抓图代码。

自动抓图执行前先判断：

- 通道是否存在
- `source_url` 是否有效
- 当前是否已经存在可用底图

若已有有效底图，则跳过。

若无有效底图，则执行抓图并更新：

- `snapshot_url`
- `snapshot_path`
- `updated_at`

### 3. 失败策略

抓图失败不抛回给创建/同步主流程。

处理方式：

- 仅记录日志
- `snapshot_url` / `snapshot_path` 保持为空或保持原值

本次不新增数据库字段记录错误信息，保持最小改动。

## 数据落库规则

继续沿用现有字段：

- `snapshot_url`：给前端和静态资源访问使用
- `snapshot_path`：给后端本地文件访问使用

抓图成功后需要同时更新：

- `backend/data/channels/*.json`
- 元数据库 `channels` 表

保证 JSON 与数据库视图一致。

## 接口影响

### 不新增接口

本次不新增对外接口。

### 保持兼容

以下接口保持不变：

- `POST /channels`
- `POST /channels/sync-wvp`
- `POST /channels/{channel_id}/snapshot`
- `GET /channels/{channel_id}/snapshot/latest`

变化仅在于：

- 通道接入后会自动异步生成底图
- 手动抓图接口变成“补抓/重抓”能力

## 代码边界

### ChannelService

负责：

- 抽取可复用的抓图内部方法
- 暴露“异步自动抓图”入口
- 本地新建通道后触发自动抓图

### WVPService

负责：

- WVP 通道落盘后触发自动抓图
- 不修改主同步接口返回结构

### metadata_db_sync

无需新增结构，只复用现有 `snapshot_url` / `snapshot_path` 同步逻辑。

## 测试要点

需要覆盖以下行为：

1. 新建通道后会调度自动抓图，但即使抓图失败，创建流程仍成功
2. WVP 同步通道后会调度自动抓图，但即使抓图失败，同步流程仍成功
3. 自动抓图成功后会写入 `snapshot_url` 和 `snapshot_path`
4. 如果通道已有有效底图，重复同步时不会重复抓图

## 预期效果

- 通道一接入，系统就会尽快生成一张底图
- `channels` 表中可以直接查到底图访问地址和本地路径
- 不再依赖人工先点一次刷新底图
- 对失败流保持容错，不影响通道接入和 WVP 同步主流程
