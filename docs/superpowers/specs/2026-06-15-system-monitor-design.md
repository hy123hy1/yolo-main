# 服务器监控页设计

## 目标

在现有 AI 视频分析平台中新增一个一级菜单“服务器监控”，用于查看当前部署本系统的这台服务器运行状态。

本次只做“查看状态”，不做运维控制，不做多服务器管理，不做告警规则配置。

## 设计范围

本次功能覆盖以下内容：

- 展示服务器基础信息
- 展示当前实时负载
- 展示最近一段时间的趋势曲线
- 支持多个时间窗口切换
- 支持自动刷新
- 在未检测到 GPU 时正常展示降级信息

本次功能不包含以下内容：

- 重启服务、停止服务、容器管理
- 多服务器列表和分组管理
- 监控数据入库
- 告警阈值、短信、邮件、Webhook 通知
- Prometheus / Grafana 集成

## 页面定位

页面为前端独立一级菜单：

- 菜单名称：`服务器监控`
- 路由建议：`/system-monitor`

该页面只面向当前系统所在主机，不需要用户额外选择服务器。

## 页面结构

页面分为三层：

### 1. 概览区

用于展示静态或低频变化的服务器信息。

建议字段：

- 服务器名称
- 在线状态
- 操作系统名称
- 操作系统版本
- 启动时间 / 运行时长
- CPU 型号
- CPU 物理核心数
- CPU 逻辑线程数
- GPU 型号
- GPU 数量
- 总内存
- 总磁盘
- 主网卡名称
- 主 IP

展示形式：

- 左侧主信息卡片
- 右侧补充信息卡片或 2 列信息网格

在线状态本次固定按“本接口可访问”视为在线，不引入额外心跳机制。

### 2. 当前负载区

用于展示实时运行状态。

建议指标：

- CPU 使用率
- 内存使用率
- GPU 使用率
- GPU 显存使用率
- 磁盘使用率
- 网络上行速率
- 网络下行速率

展示形式：

- 卡片式指标块
- 每张卡片展示当前值、单位、简短说明
- GPU 不可用时，卡片显示“未检测到 GPU”

### 3. 趋势区

用于展示最近一段时间的负载曲线。

时间窗口：

- `5 分钟`
- `30 分钟`
- `1 小时`
- `6 小时`
- `24 小时`

趋势图建议包含：

- CPU 使用率曲线
- 内存使用率曲线
- GPU 使用率曲线
- 网络速率曲线

磁盘一般变化较慢，本期可只展示当前值，不强制进入趋势图。

## 交互规则

### 自动刷新

- 页面进入后自动加载概览和当前指标
- 默认每 `5 秒` 刷新一次当前指标
- 趋势图数据也按同周期更新
- 页面离开时停止定时器

### 时间窗口切换

- 点击不同时间窗口标签后，请求对应窗口的趋势数据
- 切换时保留当前页面其他信息，不整页闪烁

### 异常展示

当监控接口异常时：

- 概览区保留上次成功数据，页面顶部提示“监控数据获取失败”
- 当前负载区可显示“暂时无法更新”
- 趋势图区域显示空态或错误提示

### GPU 降级

如果服务器没有 NVIDIA GPU，或运行环境无法读取 GPU 指标：

- 概览区显示“未检测到 GPU”
- 当前负载区 GPU 卡片显示不可用
- 趋势图中 GPU 图表显示空态说明，不报错

## 后端设计

### 总体思路

后端新增一组本机监控接口，由 Python 服务直接采集当前主机信息。

数据分两类：

- 静态信息：主机名、系统、CPU 型号、总内存、总磁盘、网卡等
- 动态信息：CPU、内存、GPU、网络速率等

动态信息不入数据库，先放内存环形缓存。

### 采集方式

优先采用：

- `psutil`：CPU、内存、磁盘、启动时间、网络流量、网卡信息
- `platform` / `socket`：主机名、系统信息
- NVIDIA 指标：优先尝试 `pynvml`，若环境不可用则降级为空

如果当前项目未安装 `psutil` 或 `pynvml`，本次实现中补充依赖。

### 数据缓存

后端维护一个进程内监控缓存服务：

- 固定采样周期：`5 秒`
- 每次采样记录一条时序点
- 保存最近 `24 小时` 以内的采样数据

缓存建议采用内存列表或按指标维护的环形队列，不进入数据库。

按 `5 秒` 采样计算，24 小时约 `17280` 个点，当前规模可接受。

`GET /system-monitor/history?window=5m|30m|1h|6h|24h`

### 服务职责拆分

建议新增以下职责：

- 路由层：暴露 `summary/current/history` 接口
- 系统监控服务：负责采集、缓存、窗口过滤、格式化返回
- GPU 采集辅助：封装成独立方法，避免主逻辑臃肿

不建议把采集逻辑直接堆在路由文件中。

## 前端设计

### 页面职责

前端新增独立页面：

- 文件建议：`frontend/src/pages/SystemMonitor.vue`

页面职责：

- 首次加载概览、当前负载和默认窗口趋势数据
- 定时刷新当前值与趋势数据
- 切换时间窗口
- 处理空态、错误态、GPU 不可用态

### API 封装

新增前端 API 文件：

- `frontend/src/api/systemMonitor.ts`

建议方法：

- `getSystemMonitorSummary()`
- `getSystemMonitorCurrent()`
- `getSystemMonitorHistory(window)`

### 图表

项目中已存在 `echarts` 和 `vue-echarts`，本次直接复用。

图表要求：

- X 轴使用时间
- Y 轴显示百分比或速率
- 网络图支持上行/下行双线
- GPU 不可用时不渲染报错图，显示占位说明

### 菜单与路由

需要新增：

- 路由注册：`/system-monitor`
- 顶部导航入口：`服务器监控`

保持当前系统中文菜单风格，不修改其他菜单结构。

## 性能与稳定性考虑

### 1. 不入数据库

监控数据是高频短周期数据，本期不入库，避免增加数据库写压力与表膨胀。

### 2. 控制刷新频率

默认 `5 秒` 刷新一次即可，避免前端频繁请求和后端过度采样。

### 3. 网络速率计算

网络速率需通过前后两次网络累计字节做差计算，不应直接读取累计值后原样返回。

### 4. GPU 可选依赖

GPU 指标必须做可选实现，不能因为机器没有显卡或缺少 NVML 依赖导致整个监控页不可用。

## 验收标准

完成后应满足：

- 顶部菜单可进入“服务器监控”页面
- 页面能展示当前服务器基础信息
- 页面能展示当前 CPU、内存、磁盘、网络负载
- 有 GPU 时可展示 GPU 信息，无 GPU 时正常降级
- 页面支持 `5分钟 / 30分钟 / 1小时 / 6小时 / 24小时` 趋势切换
- 页面自动刷新且切出页面后不会残留定时器
- 接口异常时页面能正常提示，不出现白屏
